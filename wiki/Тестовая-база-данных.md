# Тестовая база данных

Пакет создаёт пустую схему MySQL в `{database}_test`.  
**Строки рабочей базы не копируются** — только DDL таблиц и представлений.

## Pest: `TestDatabase`

Класс `\Kosmosafive\Bitrix\Tests\Database\TestDatabase`.

Подключается автоматически из `Pest\BitrixTestCase::setUpBeforeClass()` через `useClone()`.

### Когда схема пересоздаётся

| Условие | Действие |
|---------|----------|
| Базы `{database}_test` нет | Создаётся и наполняется схемой |
| Число таблиц + view разошлось с исходной БД | Схема пересоздаётся |
| `RECREATE_TEST_DB=1` (или `true` / `yes`) | Принудительное пересоздание |
| Число совпадает и флаг не задан | Используется существующая схема |

Вопрос в консоли **не задаётся** — режим CI-friendly.

### Truncate

```php
TestDatabase::truncate(['b_example']);
// или из теста:
$this->truncateTables(['b_example']);
```

Вызов вне БД с суффиксом `_test` завершится исключением.

### Защита

- отказ клонировать БД, которая уже заканчивается на `_test`;
- отказ делать `TRUNCATE` вне тестовой БД.

## PHPUnit Integration\TestCase

Класс `\Kosmosafive\Bitrix\Tests\PHPUnit\Integration\TestCase` использует свой интерактивный сценарий:

1. Если тестовой БД нет — создаётся.
2. Если число таблиц/view отличается — пересоздаётся.
3. Если число совпадает и есть интерактивный терминал — вопрос «Recreate tables?».
4. В «тихом» режиме (coverage, без TTY) при совпадении числа таблицы не пересоздаются.

Для принудительного обновления схемы перед CI удобнее Pest + `RECREATE_TEST_DB=1`.
