# Структура тестов

Тесты группируются по модулям.
В корневой директории модуля создайте директорию `tests`.
Директории и файлы именуются в CamelCase.

## Типы тестов

| Тип | Назначение |
|-----|------------|
| **Unit** | Тесты отдельных классов и функций. Гарантируют соответствие единицы заданной схеме поведения. |
| **Integration** | Тесты сценариев. Могут использовать сервисы из контейнера, тестовую БД и т.д. |
| **Application** | Тесты приложения: страница сайта, внешние сервисы. |
| **Architecture** | Архитектурное тестирование. |
| **Stress** | Нагрузочное тестирование. |

Дальнейшая структура директорий и файлов должна повторять структуру модуля относительно `lib`.

Соглашение об организации тестов для классов вне `lib` пока не зафиксировано.

## Namespace и имена

- Namespace: `{module_name}\Tests\{type}\{path}`  
  Пример: `Example\Main\Tests\Integration\Domain\Service`
- Класс: `{class_name}Test`  
  Пример: `ExampleServiceTest`
